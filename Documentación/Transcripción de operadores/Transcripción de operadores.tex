	\section{Operadores de Comparación}
		\noindent Un detalle a observar en las funciones \textit{LessThan()} y \textit{LessThanEq()} es que para números negativos podría presentar problemas. 
		
		\vspace{0.2cm}
		
		\noindent El funcionamiento de \textit{Num2Bits(n)} cuando recibe un número negativo es el siguiente:
		
		\begin{itemize}
			\item El número negativo se interpreta como un cuerpo finito.
			
			\item Éste se interpretará como un número superior a \(2^n - 1\), saliéndose fuera del rango [0,\(2^n-1\)], por tanto la constraints no se pueden cumplir y la prueba no se generará.
			
			\item En conclusión, con \textit{Num2Bits()} garantizamos el uso de número positivos dentro del rango mencionado de manera implícita.
		\end{itemize}
		
		\noindent \textit{Observación: Gracias a la constraint lc1 === in (fuerza a que la entrada cumpla el rango \([0,2^n -1]\)), podemos evitar el uso de número negativos, ya que estos no cumplirán tal restricción.}
		
		\vspace{5cm}
		
		\textbf{\textit{Num2Bits(n):}}
		
		\begin{lstlisting}[language=Circom]
			template Num2Bits(n){
				signal input in;
				signal output out[n];
				var lc1=0; // Reconstruye el numero decimal a convertir para la constraint
				
				var e2=1; // Evitar la potencia
				for (var i = 0; i<n; i++) {
					out[i] <-- (in >> i) & 1; // Contruimos el numero en binario
					out[i] * (out[i] -1 ) === 0;
					lc1 += out[i] * e2;
					e2 = e2+e2;
				}
				
				lc1 === in; // Constraint mencionada anteriormente
			}
		\end{lstlisting}
		
		\vspace{0.5cm}
		
		\noindent Partiendo de esta información, podemos realizar pequeñas modificaciones en las funciones \textit{LessThan()} y \textit{LessThanEq()} para asegurar el uso de enteros positivos.
		
		\vspace{0.2cm}
		
		\begin{tabular}{|p{0.45\textwidth} | p{0.45\textwidth}|}
			\hline
			\lstset{language=Circom}
			\begin{lstlisting}[language=Circom]
				template SecureLessThan(n){
					signal input in[2];
					signal output out;
					
					//------------------
				
					component checkA = Num2Bits(n);
					checkA.in <== in[0];
					
					component checkB = Num2Bits(n);
					checkB.in <== in[1];
					
					 adder = BinSum(n, 2);
					
					var i;
					for (i=0;i<n;i++) {
						checkA.out[i] ==> adder.in[0][i];
						checkB.out[i] ==> adder.in[1][i];
					}
					
					// Miramos el bit + significativo (MSB), 1 si A < B, 0 de lo contrario
					adder.out[n-1] ==> out;
				}
			\end{lstlisting} 
			
			&
			% Código en CIrcom
			
			\begin{lstlisting}[language=Circom]
				template SecureLessThanEq(n){
					signal input in[2];
					signal output out;
					
					//----------------------
					component checkA = Num2Bits(n);
					checkA.in <== in[0];
					
					component checkB = Num2Bits(n);
					checkB.in <== in[1];
					
					adder = BinSum(n, 2);
					
					var i;
					for (i=0;i<n;i++) {
						checkA.out[i] ==> adder.in[0][i];
						checkB.out[i] ==> adder.in[1][i];
					}
					
					// Miramos el bit + significativo (MSB), 1 si A < B, 0 de lo contrario
					component equal = IsEqual();
					equal.in[0] <== in[0];
					equal.in[1] <== in[1]; 
					
					out <==	adder.out[n-1] + equal.out - adder.out[n-1] * equal.out;
				}
				
			\end{lstlisting}
			\\
			\hline
		\end{tabular}
			
		\vspace{0.3cm}	
		
		\noindent Con está pequeña modificación, al usar para ambos número a comparar la función \textit{Num2Bits()} nos aseguramos de que se cumpla la restricción de ser número enteros positivos dentro del rango.
		
		\vspace{0.3cm}	
		
		\begin{tabular}{|c|>{\centering\arraybackslash}p{5cm}|p{8cm}|}
			\hline
				\textbf{C} & \textbf{Circom} & \textbf{Comentario} \\
			\hline
				\texttt{a == b} & \texttt{IsZero()(a - b)} & Si \(a = b\), entonces se cumple (==1) \\
			\hline
				\texttt{a != b} & \texttt{1- IsZero()(a - b)} & Si \(a \neq b\), entonces es falso (==0), por tanto se invierte con la resta \\
			\hline
				\texttt{\(a < b\)} & SecureLessThan(n)(a,b) & Si \(a < b\) es verdadero, entonces se cumple (==1) \\
			\hline
				\texttt{\(a \leq b\)} & SecureLessThanEq(n)(a,b) & Si \(a \leq b\) es verdadero, entonces se cumple (==1) \\
			\hline
				\texttt{\(a > b\)} & 1- SecureLessThanEq(n)(a,b) & Si \(a \leq b\) es falso (== 0), entonces \(a > b\) \\
			\hline
				\texttt{\(a \geq b \)} & 1- SecureLessThan(n)(a,b) & Si \(a < b\) es falso (== 0), entonces \(a \geq b \) \\
			\hline
		\end{tabular}
		
		\smallskip
		
		\vspace{0.1cm}
		
		\noindent \textit{Nota:} Las funciones \texttt{IsZero()} son circuitos que comparan si un valor es igual a 0.
		
		\noindent \textit{Nota:} Las funciones \texttt{IsEqual())} comprueba si dados dos números, estos son iguales o no.
		
		\section{Operadores Aritméticos}
		
		\noindent Tanto en C como en Circom, los operadores suma (+), resta (-) y multiplicación (*) no difieren. En cambio, en operaciones como la división entera (/) y el módulo (\%) si que encontramos diferencias y por ende es necesaria su transcripción.
		
		\vspace{0.3cm}
		
		\noindent La idea desde la que se parte para encontrar esta equivalencia es de la propiedad fundamental de la división entera, la cual establece:
		
		\[
		\scalebox{1.2}{$a = b \cdot q + r$}
		\]
		
		\vspace{0.3cm}
		
		\subsection*{Operación división}
		
		\noindent Partiendo de la fórmula \(a = b * q + r\), podemos llegar al resultado de la operación \(a / b\) forzando a que se cumpla la fórmula pero despreciando el resto (ya que se trata de división entera).
		
		\vspace{0.3cm}
		
		\noindent El término "forzar" hace referencia a usar una variable en Circom, de forma que partiendo del dividendo y del divisor, el cociente solo pueda tener ese valor.
		
		
		Ejemplo de código en Circom:
		
		\begin{lstlisting}[language=Circom]
			template IntegerDivision() {
				signal input a; // Dividendo
				signal input b; // Divisor
				signal output c; // Cociente q
				
				var q;
				a === b * q;
				c <== q;
			}
			
			component main = IntegerDivision();
		\end{lstlisting}
		
		\subsection*{Operación módulo}
		
		\noindent Partiendo de la fórmula \(a = b * q + r\), podemos llegar al resultado de la operación \(a \% b\) con la variable r, la que representa el resto de una división.
		
		\vspace{0.2cm}
		
		\noindent Por otro lado, ha de cumplirse la expresión \(0 \leq r < b\). De lo contrario, podría producirse problemas en cuanto a la seguridad del circuito. 
		
		\begin{align}
			a &= b \cdot q + r \\
			r &= a - (b \cdot q) \\
			r &= a - (b \cdot ( a / b) )
		\end{align}
		
		\noindent \textit{Nota: } q representa el resultado de una división, por lo que podemos decir que \( q = a/b \).
		
		\vspace{0.4cm}
		
		\noindent Para que se cumpla la restricción \(0 \leq r < b\) :
		
		\begin{lstlisting}[language=Circom]
			component lessThan = SecureLessThan(n);
			lessThan.in[0] <== r;
			lessThan.in[1] <== b;
			
			// 1 si r < b, como ya se checkea en SecureLessThan que sea positivo o 0 es suficiente
			
			lessThan.out === 1 // Hacemos que se cumpla la restriccion,
			// Si no se cumple, no se generara la prueba
		\end{lstlisting}
		
		\vspace{0.2cm}
		
		\begin{tabular}{|c|>{\centering\arraybackslash}p{5cm}|p{8cm}|}
			\hline
			\textbf{C} & \textbf{Circom} & \textbf{Comentario} \\
			\hline
			\texttt{\(a / b\)} & \texttt{a === b * q + r} & Forzando q con una variable a que esa ecuación se cumpla \\
			\hline
			\texttt{\(a \% b\)} & \texttt{a - (b * (a/b))} & \(a / b\) hace referencia a la equivalencia que se obtiene en circom para poder realizar la operación \% \\
			\hline
		\end{tabular}
		
		\section{Acceso a Arrays}
		
		\noindent La diferencia principal entre C y Circom en el acceso a arrays radica en que el tamaño de los arrays en Circom ha de ser fijo a la hora de compilar y ser siempre constante, mientras que en C puede ser estático y dinámico. Además, en Circom el valor de los arrays no puede ser reasignado dinámicamente.
		
		\vspace{0.3cm}
		
		\noindent \textit{Nota: En C, el tamaño de un array puede ser variable, ya sea por arrays de longitud variable o por el uso de memoria dinámica}
		
		\vspace{0.3cm}
		% Tabla con codigo C y Circom
		
		\begin{tabular}{p{0.45\textwidth} | p{0.48\textwidth}}
			\hline
			% COdigo en C
			\lstset{language=C}
			\begin{lstlisting}
				// Codigo en C
				#include <stdio.h>
				
				int main() {
					
					// Ejemplo de array con tamanyo variable con funcion f() 
					int n = f();
					int lista[n]; // Se decide en tiempo de ejecucion
					
					
					// EJemplo de array de tamanyo variable con asignacion de memoria dinamica
					int *lista = malloc(x);
					
					//x tamanyo que se quiera reservar en memoria dinamica
				}
			\end{lstlisting} 
			
			&
			% Código en CIrcom
			
			\begin{lstlisting}[language=Circom]
				
				//Codigo circom
				template accesoArray(N) {
					signal input lista[N]; // Tamanyo fijo, suponemos iniciada
					signal output sumaAcumulada;
					
					var suma = 0;
					for(int i = 0; i < N; i++){
						suma = suma + lista[i];
						
						// NO se puede hacer lo siguiente
						// lista[i] <== 3;
					}
					
					sumaAcumulada <== suma;
				}
				
				component main = accesoArray(10);
			\end{lstlisting}
			\\
			\hline
		\end{tabular}
	
		\vspace{0.4cm}
		
		\noindent \textit{Nota: En Circom no se puede fijar el tamaño de un array con una señal.}
		
		\vspace{2.6cm}
		
		\noindent En Circom, no se puede acceder directamente a posiciones de arrays con señales inputs. Sin embargo, se puede acceder indirectamente a esta posición sin usar esta señal input.
		
		\vspace{0.4cm}
			
		\begin{lstlisting}[language=Circom]
			signal input pos;
			signal input lista[N]; 
			signal output acceso;
			
			// NO SE PUEDE HACER
			//lista[pos];
			
			// SI SE PUEDE HACER, coste O(N)
			// Hay otras formas como arboles que reducen el coste a O(log (N))
			for(int i = 0; i < N; i++){
				signal seleccionado;
				seleccionado <== (i === pos ? 1 : 0);
				acceso <== acceso + lista[i] * seleccionado;
			}
			
		\end{lstlisting}
		
		\section{Expresiones condicionales}
		
		\noindent En C, al ser un lenguaje de ejecución dinámica, los condicionales pueden decidir el valor final de una variable en tiempo de ejecución.
		
		\vspace{0.3cm}
		
		\noindent En Circom, cada signal representa un “cable” del circuito, que solo puede recibir un valor. Por ello, no es posible reasignar un signal dentro de un condicional dinámico. 
		
		\vspace{0.3cm}
		
		\noindent Para simular decisiones condicionales basadas en entradas (inputs), se deben usar expresiones aritméticas que implementen la lógica de selección, de manera que el valor de salida quede correctamente definido sin reasignar el signal.
		
		\vspace{0.3cm}
		% Tabla con codigo C y Circom
		
		\begin{tabular}{p{0.45\textwidth} | p{0.45\textwidth}}
			\hline
			% COdigo en C
			\lstset{language=C}
			\begin{lstlisting}
				// Codigo en C
				#include <stdio.h>
				
				int main(int argc, char *argv[]) {
					int entrada = argv[1];
					char mensaje[50];
					
					if(entrada % 2 == 0){ 
						sprintf(mensaje, "%d es par\n", entrada);
					}
					else {
						sprintf(mensaje, "%d es impar\n", entrada);
					}
					
					printf("s", mensaje);
					free(mensaje);
					
					return 0;
				}
			\end{lstlisting} 
			
			&
			% Código en CIrcom
			
			\begin{lstlisting}[language=Circom]
				
				//Codigo circom
				template condicionales() {
					signal input entrada;
					signal output salida; //0 par, 1 impar
					
					var var_division;
					entrada == 2 * var_division;
					
					salida <== (entrada - (2*var_division)) 
					
				}
				
				component main = condicionales();
			\end{lstlisting}
			 \\
			 \hline
		\end{tabular}
		
		\vspace{0.3cm}
		
		\noindent Con este ejemplo se ilustra como puede transformarse una expresión condicional que comprueba si un número es par o impar en una expresión aritmética que representa lo mismo y evita el reasignar la señal de salida más de una vez (algo no permitido).
		
		\section{Operadores de desplazamiento}
		
		\noindent Los operadores de desplazamiento en C funcionan de la siguiente manera:
		
		\vspace{0.3cm}
		
		\noindent Imaginemos que tenemos el número 2 que queremos desplazar 2 bits
	
		\begin{itemize}
			\item 1. Dado un número decimal 2, transformarlo a binario, que es 0010
			\item 2. Con el n (número de bits a desplazar), desplazamos los dos últimos bits
			\item 1000 (4 en decimal), es el número que se obtiene desplazando los bits
		\end{itemize}
		
		\vspace{0.1cm}
		
		\noindent \textit{Observación: Podemos observar que para obtener el número equivalente del desplazamiento de bits en decimal se consigue con x * $2^n$ en el caso de desplazamiento a la derecha y x * $2^n$ en el caso de desplazamiento a la izquierda.}
		
		\vspace{0.3cm}
		
		\noindent Podemos hacer uso de esta observación para llegar a la equivalencia de tal operación en Circom.
		
		\vspace{0.4cm}
		
		\begin{tabular}{|c|>{\centering\arraybackslash}p{15cm}|}
			\hline
			\textbf{C} & \textbf{Circom} \\
			\hline
			\texttt{$a \ll b$ } & 
			
			\begin{lstlisting}[language=Circom]
				
				//Codigo circom
				template desplazamiento_izq(N) {
					signal input numero_decimal;
					signal output salida;
					
					var potencia = 1;
					
					for (var i = 0; i < N; i++) {
						potencia = potencia * 2;
					}
					
					salida <== numero_decimal * potencia;
					
				}
				
				component main = desplazamiento_izq(N);
			\end{lstlisting}
			 
			\\
			\hline
			\texttt{{$a \gg b$ }} & 
			
			\begin{lstlisting}[language=Circom]
				
				//Codigo circom
				template desplazamiento_dcha(N) {
					signal input numero_decimal;
					signal output salida;
					
					var potencia = 1;
					
					for (var i = 0; i < N; i++) {
						potencia = potencia * 2;
					}
					
					var division;
					
					numero_decimal === potencia * division;
					
					salida <== division;
					
				}
				
				component main = desplazamiento_dcha(N);
			\end{lstlisting}
			
			
			\\
			\hline
		\end{tabular}
